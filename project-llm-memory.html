Compiling Intelligence: LLM-Generated Memory for Smarter Agents

Why machines should write their own context — and why it works better

📅 April 2026 ✍️ Wenxue Cao 🏷️ AI · LLM Agents · Memory Systems 🖨 Save as PDF
LLM Agents Memory Architecture RAG MemGPT Reflexion Agent Harness

The Amnesia Problem

Every time you start a new conversation with an AI assistant, it forgets everything. Not just the last conversation — it forgets every conversation, every lesson learned, every mistake corrected. Andrej Karpathy captured this precisely when he described LLMs as suffering from anterograde amnesia: their weights are frozen at training time, and the context window — their working memory — resets to zero at the start of every session.

Karpathy's framing is illuminating: think of the LLM as a CPU, its context window as RAM, and its weights as slow, read-only storage. The problem is that this RAM is extremely limited — a few hundred thousand tokens at most — and is wiped clean between sessions. Everything a model "knows" about your specific project, preferences, or history has to be re-read from scratch every single time.

Karpathy's LLM OS Analogy (2023)

"The LLM is the CPU. The context window is RAM. The weights are disk — slow, read-only, and frozen. The agent needs an OS to manage memory across sessions."

This creates a fundamental inefficiency. To give a model the context it needs to function well on a long-running project, you either cram everything into a single enormous context window (slow, expensive, and often not even enough), or you build a retrieval system that pulls relevant pieces when needed. The second approach — Retrieval Augmented Generation (RAG) — has become the dominant solution. But as we'll see, it introduces its own serious limitations.

Why Human-Built Knowledge Bases Fall Short

RAG works by indexing a collection of documents and retrieving the most semantically similar chunks whenever the model needs information. It is a powerful technique, but its fundamental architecture is built for humans: the documents are written by humans, organised by humans, and indexed according to human-defined categories. The LLM is just a reader.

❌ Traditional RAG

  • Static, read-only document index
  • Written and organised by humans
  • Retrieves on semantic similarity only
  • No accumulation — every query starts fresh
  • Misses non-obvious cross-references
  • Knowledge never improves from usage

✅ LLM-Generated Memory

  • Dynamic, writable memory store
  • Written and organised by the agent itself
  • Retrieval informed by accumulated context
  • Compounding — knowledge builds over time
  • Cross-references created automatically
  • Self-corrects as new information arrives

The Letta team (creators of MemGPT) articulate the core architectural flaw of RAG clearly: it has no write path. Every query to a RAG system begins from the same fixed index. The system cannot learn that two seemingly unrelated documents are actually deeply connected, cannot flag contradictions discovered during a session, and cannot accumulate the kind of tacit understanding that makes an expert's knowledge qualitatively different from a beginner's.

But there is a deeper problem, one that is easy to overlook: human-written knowledge is optimised for human readers, not for LLMs. Humans write in narrative prose with cultural context, implicit assumptions, and rhetorical structure. An LLM reading such text must first decode all of that before it can extract the underlying information. This is inefficient, and it introduces noise — the model may focus on stylistic features rather than semantic content.

The Core Insight: LLMs Should Write for Themselves

The key insight that motivates a new generation of memory architectures is deceptively simple: memory generated by an LLM is more efficiently read by an LLM than memory written by a human.

When an LLM writes a summary, a note, or a structured entry in its own knowledge base, it naturally organises information in the format it finds most useful for retrieval. It uses the vocabulary, abstraction level, and logical structure that maps most directly onto its own internal representations. Reading this back is fundamentally cheaper — in both computational and representational terms — than parsing human prose.

Karpathy formalised this in his proposal for an "LLM-maintained wiki": a structured Markdown knowledge base that an agent incrementally builds, updates, and cross-references. He draws a compelling analogy to compilation: raw documents are source code; the LLM-compiled wiki is the executable. You do not re-compile from source every time you run a program — you run the compiled artefact. Similarly, rather than re-reading source documents on every query, the agent reads and extends its own compiled knowledge.

The Compiler Analogy (Karpathy, 2025)

Raw documents are source code. The LLM-generated wiki is the compiled executable. RAG re-compiles from source on every query; agent memory runs the compiled artefact directly — faster, richer, and self-improving.

MemGPT: Virtual Context Management

Packer et al. (2023) drew directly on operating systems theory. Just as an OS manages a memory hierarchy — registers, RAM, disk — MemGPT gives an LLM agent a fast in-context tier (analogous to RAM) and a slower external storage tier (analogous to disk), with the LLM itself deciding what gets paged in and out via tool calls. This allows the agent to maintain coherent, long-term memory across sessions far exceeding the context window, without requiring the model to hold everything in working memory at once.

Reflexion: Learning Through Verbal Self-Reflection

Shinn et al. (NeurIPS 2023) demonstrated that LLM-generated verbal reflections — written by the agent after a failed attempt — function as a more efficient form of memory than re-reading task specifications or external documentation. After each trial, the agent writes a self-critique in natural language, which is stored in an episodic memory buffer and re-injected as context in the next attempt. Reflexion achieved 91% pass@1 on HumanEval, surpassing GPT-4's 80%, purely through self-generated memory without any gradient updates or model retraining.

A-MEM: Agentic Memory with Zettelkasten

Xu et al. (2025) drew on the Zettelkasten note-taking philosophy to build a self-organising memory network. When a new memory is stored, the agent automatically generates structured notes, keywords, and links to existing memories. Critically, it can retroactively update older memories as new information arrives — the knowledge base is never static but evolves through the agent's own operations, creating a living graph of interconnected knowledge that grows more useful over time.

Harness Engineering: Externalising Cognitive Load

A 2026 survey on LLM agent design argues that the most significant capability gains in modern agents come not from changing model weights but from externalising cognitive load into memory stores, reusable skills, interaction protocols, and an orchestrating "harness." The harness is the infrastructure that manages when to read from memory, when to write, when to retrieve, and how to maintain coherent state across a long-running task — a role analogous to the operating system in classical computing.

A Concrete Example: Claude Code's Memory System

An instructive real-world example is the memory system used by Claude Code, Anthropic's AI coding assistant. Rather than asking the user to maintain a context document, or building a static knowledge base of project facts, Claude Code writes its own Markdown memory files as it works — capturing user preferences, project conventions, key decisions, and lessons learned. On subsequent sessions, it reads these self-generated files to restore context.

The files are structured, indexed, and written in a format the model finds easy to parse — not because a human designed that format, but because the model itself chose how to represent information when writing it. The result is faster context restoration, more accurate preference recall, and a compounding improvement in collaboration quality that a static RAG system could not achieve.

This is exactly the "compiled wiki" pattern: the agent acts as both writer and reader of its own knowledge base, continuously compiling raw experience into structured, efficiently retrievable memory.

Why This Matters: Efficiency and the Retrieval Gap

The efficiency argument runs deeper than just storage format. When an LLM reads a human-written document, it must spend representational capacity on parsing rhetorical structure, resolving ambiguity, handling implicit assumptions, and translating domain vocabulary. When it reads its own structured memory, much of this overhead is eliminated — the information is already in the form most directly useful for the task at hand.

The retrieval gap matters too. RAG retrieves on semantic similarity, which means it will miss information that is logically relevant but lexically distant — a connection between a constraint mentioned in one document and a design decision documented in another, for instance. An LLM-generated memory, built through active reasoning about the task, can create those cross-references explicitly at write time, so they are available at retrieval time without requiring complex re-reasoning.

The position paper on episodic memory (2025) frames this as the missing piece for long-term agents: biological episodic memory encodes specific past experiences in a way that can be retrieved and replayed. Current LLM systems lack this — they either re-derive knowledge from scratch (expensive and error-prone) or rely on static retrieval that misses the experiential dimension. LLM-generated memory is the closest computational analogue.

Limitations and Open Questions

LLM-generated memory is not without challenges. If the model writes incorrect information into its memory store, those errors persist and compound — the system may become confidently wrong over time. This "hallucination propagation" problem requires careful design: memory should ideally include confidence scores, source references, and mechanisms for detecting and correcting contradictions.

Scalability is another concern. As the memory store grows, retrieval must remain efficient. The A-MEM approach of maintaining explicit cross-reference links helps, but managing a large, self-organised knowledge graph at inference time is computationally non-trivial.

There is also the question of what the model does not know to write down. Human-designed knowledge bases benefit from expert curation — a domain expert knows which facts are important enough to document. An LLM agent writing its own memory may systematically under-represent certain types of information that it does not currently perceive as relevant but that will matter later.

Conclusion

The shift from human-built knowledge bases to LLM-generated memory represents a fundamental change in how we think about agent cognition. It moves the agent from a passive reader of externally organised information to an active author of its own context — compiling raw experience into structured, self-referential knowledge that grows more useful over time.

The analogy to compilation is apt: just as compiled code runs faster than interpreted code precisely because the hard work of translation has been done in advance, LLM-generated memory enables faster, more accurate reasoning because the hard work of contextualisation has already been done by the agent itself. The intelligence is not just in the model — it is increasingly in the harness that surrounds it.

As LLM agents take on longer-horizon tasks, the ability to build and maintain their own memory will become as important as the quality of the underlying model. The most capable agents of the near future will not be the ones with the largest context windows — they will be the ones that know best how to compile their own intelligence.
